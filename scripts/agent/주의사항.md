# 노션 데이터 손보기 — 주의사항

> `scripts/agent/enricher.ts` 를 고치거나 비슷한 스크립트를 새로 만들 때 **먼저 읽습니다.**
> 여기 적힌 건 전부 한 번씩 실제로 겪은 것들입니다. 같은 데서 두 번 넘어지지 않으려고 적어둡니다.

---

## 1. 데이터를 덮어쓰기 전에 — 제일 중요

**AI가 실패했을 때 원본을 지우면 안 됩니다.**
AI 호출이 실패하거나 이상한 답을 하면, 고치지 말고 **원래 글을 그대로 둡니다.**
예전에 이 규칙이 없어서 멀쩡한 툴 2,000건을 날릴 뻔했습니다 (`worker/src/enrich.ts` 주석 참고).

지키는 방법:
- AI 답이 너무 짧거나(20자 미만), 너무 길거나(200자 초과), 여전히 깨져 있으면 → `null` 로 버리고 원본 유지
- 실제로 바뀐 값이 하나도 없으면 노션에 UPDATE 요청 자체를 보내지 않음

**항상 `--dry-run` 을 먼저 돌립니다.** 뭐가 바뀔지 눈으로 본 다음에 진짜로 돌립니다.

```bash
npm run enrich:notion -- --limit=5 --dry-run   # 먼저 이걸로 확인
npm run enrich:notion -- --limit=15            # 확인됐으면 진짜로
```

## 2. 노션 API (v5) — 예전 방식이 안 됩니다

설치된 `@notionhq/client` 는 **v5** 입니다. 예전 코드/블로그와 방식이 다릅니다.

| 하면 안 되는 것 | 해야 하는 것 |
|---|---|
| `notion.databases.query({ database_id })` | `notion.dataSources.query({ data_source_id })` |
| DB id 를 바로 질의에 씀 | DB 를 먼저 `retrieve` → `data_sources[0].id` 를 꺼내서 씀 |

그 id 를 꺼내는 함수는 이미 있습니다: `worker/src/notion.ts` 의 `getDataSourceId()`. **새로 만들지 말고 그걸 쓰세요.**

**속성 이름은 한글입니다.** 노션에서 이름을 바꾸면 코드도 같이 바꿔야 합니다.

```
이름(title) / URL(url) / Description(rich_text) / 소개글(rich_text)
Source(rich_text) / 날짜(date) / 카테고리(select) / 가격(select) / 한국어(checkbox)
```

**노션 필터로 못 하는 것:** "설명이 20자 미만" 같은 길이 조건은 노션 API에 없습니다.
그래서 100건씩 받아와서 코드에서 직접 걸러냅니다. 필터로 하려고 시간 쓰지 마세요.

**글자 수 제한:** rich_text 한 칸에 2,000자까지. 넘으면 API가 거절합니다.

## 3. 속도 제한 — 노션은 초당 3건

- 호출 사이에 **400ms** 씩 쉽니다. 이건 협상 대상이 아닙니다.
- 그래도 429가 오면 응답의 `retry-after` 초만큼 쉬고 넘어갑니다.
- 한 건이 실패해도 **절대 멈추지 않습니다.** 로그만 남기고 다음 건으로 갑니다. 남은 건 다음 실행 때 다시 잡힙니다.

## 4. 새 라이브러리 설치 금지 (CLAUDE.md 규칙 7)

이 스크립트는 **새로 설치한 게 하나도 없습니다.** 다음은 전부 필요 없습니다:

| 흔히 설치하려는 것 | 대신 쓰는 것 |
|---|---|
| `tsx` | `node --experimental-strip-types` (Node 24는 기본 지원) |
| `dotenv` | `node --env-file-if-exists=...` |
| `axios` / `node-fetch` | Node 기본 `fetch` |
| `tavily` / `serpapi` | 이미 쓰고 있는 **네이버 검색** (`resolveOfficialUrl`) |
| `@google/genai` / `openai` SDK | `fetch` 로 제미나이 REST 직접 호출 |

## 4-1. 제미나이에서 실제로 걸렸던 것 (전부 한 번씩 당했습니다)

**① 좋은 모델은 무료로 하루 20건밖에 못 씁니다.**
`gemini-flash-latest`(= gemini-3.6-flash)의 무료 한도는 **하루 20건**입니다.
15건 한 번 돌리고 나면 그날은 끝입니다. 그래서 기본값은 `gemini-flash-lite-latest` 입니다 —
품질은 조금 낮지만 한도가 훨씬 넉넉해서 수백 건을 돌릴 수 있습니다.

한도에 걸리면 429가 오는데, **"분당 제한"과 "하루 제한"이 똑같은 429로 옵니다.**
20초 쉬고 다시 시도해도 안 되면 하루 제한에 걸린 겁니다. 에러 본문의 `quotaId` 를 보면 구분됩니다:
`...PerMinute...` = 잠깐 쉬면 됨 / `...PerDay...` = 내일까지 기다리거나 모델을 낮춰야 함.

**② `thinkingConfig: { thinkingBudget: 0 }` 은 최신 모델에서 거부됩니다 (400).**
제미나이 3.x는 '속으로 생각하는' 기능을 끌 수가 없습니다. 예전 문서를 보고 이걸 넣으면
`Request contains an invalid argument` 만 나오고 원인을 안 알려줍니다.

**③ 그래서 `maxOutputTokens` 를 넉넉히 줘야 합니다.**
생각한 분량이 이 한도에 같이 들어갑니다. 한 줄 설명 하나 받는 데도 생각에만 300~600을 씁니다.
**300으로 잡으면 생각하다 한도가 끝나서 답이 반토막 납니다.** 1,200 이상 주세요.
잘렸는지는 `candidates[0].finishReason` 으로 알 수 있습니다 — `STOP` 이 아니면 버립니다.

**④ 응답은 `candidates[0].content.parts[*].text`** — `parts` 가 여러 개로 쪼개져 올 수 있어서
하나만 꺼내지 말고 전부 이어붙입니다.

**키 위치:** `.env.local` 의 `GEMINI_API_KEY`. 발급은 aistudio.google.com (무료).
모델을 바꾸려면 `.env.local` 에 `GEMINI_MODEL=...` 한 줄만 추가하면 됩니다.
AI 호출 사이에 4초씩 쉽니다(`AI_대기`) — 15건에 1~2분 걸리는 건 정상입니다.

## 5. 이미 있는 걸 다시 만들지 않기

새로 짜기 전에 여기부터 봅니다:

| 필요한 기능 | 이미 있는 것 |
|---|---|
| 툴 이름으로 공식 홈페이지 찾기 | `worker/src/collect.ts` 의 `resolveOfficialUrl()` — 위키/유튜브/쇼핑몰 거르고, 이름이 도메인에 들어간 결과를 우선함 |
| 주소에서 도메인 뿌리만 남기기 | `siteRoot()` |
| 주소 모양 통일 (중복 방지) | `normalizeUrl()` |
| 노션 데이터소스 id | `getDataSourceId()` |
| 노션 저장용 본문 만들기 | `toNotionPage()` |

**"AI에게 홈페이지 주소를 물어보기"는 하지 마세요.** Gemini를 암호화폐 거래소(gemini.com)라고 답하는 식으로 틀립니다. 반드시 검색 결과에서 가져옵니다.

## 6. 환경변수가 두 군데에 나뉘어 있습니다

| 파일 | 들어있는 것 | 쓰는 곳 |
|---|---|---|
| `.env.local` | `NOTION_TOKEN`, `NOTION_DATABASE_ID` | 내 컴퓨터에서 도는 스크립트 |
| `worker/.dev.vars` | 위 + `NAVER_CLIENT_ID/SECRET`, `PRODUCT_HUNT_TOKEN` | 로컬 워커 |
| Cloudflare Secret | 위 전부 | 배포된 워커 (`npx wrangler secret put ...`) |

그래서 `npm run enrich:notion` 은 **두 파일을 다 읽습니다.** 새 키를 넣을 땐 어느 파일인지 확인하세요.
**키를 코드에 직접 쓰지 않습니다.** 두 파일 모두 `.gitignore` 처리돼 있습니다.

## 7. TypeScript 문법 제한 (타입만 벗겨내고 그대로 실행)

`--experimental-strip-types` 는 타입만 지우고 변환은 안 합니다. 그래서 **못 쓰는 문법**이 있습니다:

- `enum`, `namespace`, 생성자 파라미터 프로퍼티(`constructor(private x)`), 데코레이터 → 전부 에러
- import 에 **`.ts` 확장자를 반드시** 붙입니다 (`from "./notion.ts"`)
- 타입만 가져올 땐 `import type { ... }` 로 명시합니다

`tsconfig.json` 은 `scripts/` 와 `worker/` 를 제외합니다. 즉 **`npm run build` 로는 이 스크립트가 검사되지 않습니다.** 고쳤으면 직접 돌려서 확인하세요:

```bash
node --experimental-strip-types scripts/agent/enricher.ts --self-check
```

## 8. 윈도우에서 겪은 것

- `npx wrangler ... --command "SQL"` → SQL이 공백마다 쪼개져서 깨집니다. `node node_modules/wrangler/bin/wrangler.js` 로 직접 부릅니다 (`push-to-notion.ts` 참고).
- wrangler가 종료하며 내는 잡음에 진짜 에러가 묻힙니다. stderr 에서 `ERROR` 줄만 뽑아서 보여줍니다.

## 9. 고쳐도 사이트에 바로 안 보입니다

사이트는 노션 내용을 **1시간 캐시**합니다. 고치고 나서 바로 안 보이면 정상입니다. 잠시 뒤 새로고침하세요.

## 10. 매일 자정 자동 실행 (GitHub Actions)

`.github/workflows/enrich-notion.yml` 이 매일 자정(한국시간)에 돌아갑니다.
**전체 1,300건을 훑지 않습니다** — 최근 25시간 안에 노션에서 바뀐 줄만 봅니다.

```bash
npm run enrich:notion -- --조사 --최근=25   # 자동 실행이 볼 범위를 미리 확인
npm run enrich:notion -- --최근=25          # 손으로 같은 걸 돌리기
```

**24시간이 아니라 25시간인 이유:** 딱 24시간으로 자르면 실행이 몇 분만 밀려도 그 사이에 들어온 게
영영 새어 나갑니다. 한 시간 겹쳐두면 빠뜨리지 않습니다. 이미 고친 줄은 다시 부실하지 않으니
겹쳐 봐도 손해가 없습니다.

**우리가 고친 줄도 '마지막 수정 시각'이 갱신되지만 무한 반복은 안 됩니다** —
고치고 나면 판정 기준을 통과하므로 다음 날 대상에서 빠집니다. (실제로 확인했습니다:
24건을 고친 직후 `--최근=1` 로 조사하니 0건이 나왔습니다.)

**GitHub Secrets 5개가 등록돼 있어야 합니다:**
`NOTION_TOKEN` / `NOTION_DATABASE_ID` / `GEMINI_API_KEY` / `NAVER_CLIENT_ID` / `NAVER_CLIENT_SECRET`

**캐시는 일부러 안 비웁니다.** 사이트가 노션을 1시간 들고 있어서 자정에 고치면 늦어도 새벽 1시에
저절로 반영됩니다. 강제로 비우려면 클라우드플레어 토큰을 하나 더 등록해야 해서 그냥 뒀습니다.

## 11. 알려진 한계 (지금은 그냥 둔 것)

- **매번 DB 앞에서부터 훑습니다.** 고칠 수 없는 툴(주소를 아무리 검색해도 안 나오는 것)이 앞에 쌓이면 실행할 때마다 같은 걸 다시 붙잡습니다. 눈에 띄게 거슬리면 노션에 `확인함` 체크박스를 하나 만들어서 거르면 됩니다.
- **판별은 글자 비율로만 합니다.** 한글·영어 아닌 글자가 12%를 넘으면 "깨진 글"로 봅니다. 일본어/중국어/아랍어는 잘 잡히지만, 영어로 멀쩡하게 쓰인 헛소리는 못 잡습니다.
